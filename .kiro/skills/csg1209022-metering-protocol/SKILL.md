# 计量自动化终端上行通信规约（Q/CSG1209022-2019）

本技能是这份标准全文的结构化知识库。标准原文约125页，已按章节拆分为 `references/` 下的多个文件，**不要一次性读取全部文件**——先看下面的索引，判断用户的问题落在哪一章/哪个AFN功能码/哪个附录，只读取相关的1~2个文件。

## 适用范围

标准规定的是**主站与计量自动化终端之间的上行通信**，适用于：厂站电能量采集终端、负荷管理终端、配变监测计量终端、低压电力用户集中抄表系统集中器。通信介质包括 TCP/UDP、串口、红外、PSTN话音MODEM、音频专线MODEM。

## 整体架构（三层参考模型）

协议基于 GB/T 18657.3 的"增强性能体系结构"三层模型：**物理层 → 链路层 → 应用层**。

帧格式采用 GB/T 18657.1 的 FT1.2 异步式传输帧：

```
68H | 长度L(2字节) | 长度L(重复) | 68H | 控制域C | 地址域A | 用户数据(应用层) | 校验和CS | 16H
```
低位在前、高位在后；低字节在前、高字节在后。

1. **先定位再读取**：根据用户问题（比如"AFN=0CH怎么解析"、"终端地址怎么编码"、"DI标识是什么"）先查上表，只读1~2个相关文件，避免一次性加载全部内容占满上下文。
2. **写代码时**：报文的通用外层结构（帧头、控制域、地址域、校验和）在 `01-链路层帧格式.md`；具体某个AFN的报文体结构在 `02` + `03a`/`03b`；报文体内的具体数据项编码在附录A~N中对应的一个。三者通常需要配合着看才能拼出完整的编解码逻辑。
3. **数据标识（DI）**是贯穿全文的核心索引机制——遇到不认识的DI编码，先去 `02-应用层通用格式.md` 看DI编码规则，再到对应附录（A/B/C/D/E）里按DI查具体定义。
4. 原文档中的表格在提取时部分表头/表体合并展示，如遇表格解析歧义，可提醒用户核对原始 Word/PDF 文档。
