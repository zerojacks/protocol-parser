文件传输

- G.1　数据标识编码定义

文件传输命令数据标识编码定义见下表G.1：

	表G.1　数据标识编码定义

| 序号 | 数据标识编码 | 名称 | 说明 |
| --- | --- | --- | --- |
|  | DI3 | DI2 | DI1 | DI0 |  |  |
| 01 | E3 | 01 | 00 | 01 | 文件传输启动 | FD1，参见表G2 |
| 02 | E3 | 01 | 00 | 02 | 传输文件内容 | FD2 |
| 03 | E3 | 01 | 00 | 03 | 查询文件信息 | FD3 |

- G.2　数据标识内容

表G.2　数据标识内容

| 编号 | 数据格式 | 字节数 | 事件数据内容 |
| --- | --- | --- | --- |
| FD1 | NNNN | 2 | 文件性质（BIN） |
|  | NNNN | 2 | 文件总段数（即文件内容传输帧数）（BIN） |
|  | NNNNNNNN | 4 | 文件大小（BIN） |
|  | NN……NN | 32 | 文件名称（ASCII） |
|  | NNNN | 2 | 总校验（CRC16校验） |
| FD2 | NNNN | 2 | 文件段号（即文件内容传输帧号），段号从0开始（BIN） |
|  | NNNN | 2 | 文件段长度（即该帧文件内容长度）（BIN） |
|  | NN…NN | — | 文件段内容，字节数由文件段长度决定（BIN） |
|  | NN | 2 | 段校验（CRC16校验） |

注1：CRC16校验生成多项式采用CRC16-CCITT（0x1021），x16+x12+x5+1。

注2：除了最后一个文件段，其他文件段的长度必须一致。假设文件大小为m字节，文件总段数为n，则每个文件段长度为floor(m/n)，最后一个文件段长度为mod(m/n)。

下行数据格式：

| FD3 | NNNN | 2 | 文件性质（BIN） |
| --- | --- | --- | --- |
|  | NNNN | 2 | 文件总段数（BIN） |
|  | NNNNNNNN | 4 | 文件大小（BIN） |
|  | NNNN | 32 | 文件名称（ASCII） |
|  | NNNN | 2 | 总校验（CRC16校验） |
|  | NNNN | 2 | 查询起始段号，BIN编码 |
|  | NNNN | 2 | 查询结束段号，BIN编码 |

上行数据格式：

| FD3 | NNNN | 2 | 文件性质（BIN） |
| --- | --- | --- | --- |
|  | NNNN | 2 | 文件总段数（BIN） |
|  | NNNNNNNN | 4 | 文件大小（BIN） |
|  | NNNN | 32 | 文件名称（ASCII） |
|  | NNNN | 2 | 总校验（CRC16校验） |
|  | NNNN | 2 | 查询起始段号，BIN编码 |
|  | NNNN | 2 | 查询结束段号，BIN编码 |
|  | NNNN | 2 | 查询起始结束段中未成功接收的总段数m（BIN） |
|  | NNNN NNNN …… NNNN | 2×m | 未成功接收的段号列表（BIN） |

注：FD1和FD3的文件性质表示对不同的设备进行升级，意义如下：

a)	00H：终端升级文件。

b)	01H: 终端普通文件。

c)	02H：远程通信模块文件。

d)	11H：集中器本地通信模块文件。

e)	12H：从节点本地通信模块文件。

f)	13H：采集器文件。

g)	0FH：清除正在传输的文件
