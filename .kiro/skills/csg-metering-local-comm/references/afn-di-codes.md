# AFN / DI 编码全表

DI is written as `DI3 DI2 DI1 DI0`. "地址域标识" column: 0 = frame carries no address domain A, 1 = frame
carries address domain A (ADD bit in control byte should match).

## 1. 集中器本地通信模块接口 (DI3 = E8)

### AFN=00H 确认∕否认
| DI | 名称 | 地址域标识 |
|---|---|---|
| E8 01 00 01 | 确认 | 0 |
| E8 01 00 02 | 否认 | 0 |

**否认错误状态字** (1 字节, 紧跟在 DI 后的数据内容):
`0`=通信超时 `1`=无效数据标识内容 `2`=长度错误 `3`=校验错误 `4`=数据标识编码不存在 `5`=格式错误
`6`=表号重复 `7`=表号不存在 `8`=电表应用层无应答 `9`=主节点忙 `10`=主节点不支持此命令
`11`=从节点不应答 `12`=从节点不在网内 `13`=添加任务时剩余可分配任务数不足
`14`=上报任务数据时任务不存在 `15`=任务ID重复 `16`=查询任务时模块没有此任务 `17`=任务ID不存在
`FFH`=其他

## 3. 判读要点

1. 先看 DI3：`E8` → 用第 1 节的表；`EA` → 用第 2 节的表。
2. DI1 应该等于 AFN 字节值（十进制/十六进制均按原文，注意 AFN 是 1 字节十六进制，DI1 也是同一十六进制
   字节）——如果两者不一致，说明帧可能损坏或不属于本协议。
3. DI2 的值（00/01/02/03/04/05/06）本身不改变查表结果，但能帮助你判断这一帧应该是上行还是下行、有无
   数据内容，与控制域的 DIR 位相互印证。
4. 确认/否认帧 (`xx 01 00 01` / `xx 01 00 02`) 可以是对**任意**命令的回复，具体是回复哪条命令要看
   SEQ 字节是否与之前下发命令的 SEQ 一致，协议本身的 DI 不体现"回复谁"。
